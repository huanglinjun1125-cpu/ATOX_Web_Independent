# 官方后台三个独立子模块路线

日期：2026-10-10（Asia/Shanghai）。按用户授权依次实施：选手材料审核 → 活动发布 → 官网内容管理。每模块单独契约、数据归属、README、验证和留存；不把后续入口伪装成已实现功能。沿用 M008 权限基础，不承诺完整生产上线。

## 1. M009 选手正式材料审核

数据来源为 M002 已提交 official，保持个人归属和私有附件；展示待审核／通过／驳回。驳回原因必填，开放期可重提（含旧 processed rejected）；accepted 只读。原截止暂延续，截止后补交待用户确认。管理员角色替代受理白名单且不自动提权旧账号。具体字段、状态映射和验收见 [M009 设计](M009-DESIGN.md)。

验收聚焦真实材料流程、权限迁移无旁路、正式／草稿隔离、修订冲突、附件隐私、重提与截止边界以及业务审核记录。不存在的独立项目投稿不列入审核队列。

## 2. 活动发布与内容管理

基于 M004／M007 的活动结构化配置实现持久化双语草稿、后台预览、发布及下架。编辑草稿不立即改公开注册表；公开看板及详情只读取发布版本，预览仅管理员访问。每次发布绑定明确修订号，避免把尚未确认的草稿直接暴露。

字段覆盖稳定活动 ID、双语名称／主题／简介／主办方／地点、封面、实际活动起止及时区、报名／提交窗口、赛道／规则、标签／推荐／入口目标／演示标记，以及已有组队配置、资料、FAQ。字段校验沿用注册表规则：开始早于结束、有效时区、链接协议、推荐唯一及活动关系。实际活动阶段与参赛窗口仍分开计算。

发布状态与阶段分别记录：草稿／已发布／已下架不等于即将开始／进行中／已结束。下架不删除报名、队伍、材料或审核历史；不得改变存量活动 ID 或重新用 ID 承载另一场活动。存量配置接入不重置用户数据。

实施前需锁定：运营发布权限、下架后本人参赛中心可见性、已产生报名后修改窗口／赛道／人数的限制，以及旧组队申请遇窗口重开的策略。未锁定这些行为不得通过通用编辑器绕过原业务限制。建议新增及编辑内容和变更业务规则分别校验，拒绝无定义的破坏性更改。

验收：草稿不影响公开站、双语预览与发布一致、非法配置拒绝、修订冲突、发布／下架审计、公开缓存与版本一致、权限及外链安全、已报名者边界明确、存量 ID／参赛数据延续、多活动隔离。

## 3. 官网结构化内容管理

基于 M005 homepageConfig，实现结构化双语首页草稿、预览、发布与下架，不提供任意代码／脚本编辑器。覆盖品牌及 metadata、首屏文案／按钮、组织介绍、主办方向、活动／项目入口、多栏页脚及可选联系方式；保持共享导航、登录状态和语言能力，不把运营内容写入认证逻辑。

首页草稿与发布版本分离；运营修改不能直接影响公开首页。下架可选内容块需有安全回退，站点必要导航及登录入口不可随意移除。整页发布版本下架后的回退策略须在该模块实施前确认；不能让普通用户读到未发布草稿。联系方式／合作方等缺省隐藏，不捏造数据。

验收：双语必填与链接校验、预览权限、发布修订绑定、草稿隔离、下架回退、图片及富文本安全、手机布局和可访问性、共享导航／登录回归、持久化与审计。只管理批准内容，不扩展任意 CMS 或页面搭建器。

## 共用规则与独立发布边界

三个模块每请求和写事务校验有效管理员，角色停用立即生效；更改携带修订号并同事务记录操作者、对象、前后状态／版本及时间。各模块使用共享数据库连接、追加迁移及独立公开入口，不重置原数据。权限审计与业务审计分别归属，不提供删除历史入口。

材料审核与活动／首页发布无联动：材料通过不会创建公开项目，活动发布不会改变个人审核结果，首页发布不会重开截止窗口。真实项目投稿、公开授权、公开附件、项目审核与发布／下架属于另行授权模块；M006 目前只有演示目录和投稿说明入口。

每阶段完成适当服务／浏览器／构建及权限回归后留存，原归档不变，排除真实密钥及用户运行数据。具体 API、模块编号和迁移由统筹在对应实施阶段确认；当前文档不宣称未实施阶段验收通过。
