# 当前架构与维护边界

更新时间：2026-10-10（Asia/Shanghai）。单 Next.js 应用、一个共享迁移历史、一个进程内 PGlite 连接，不拆分仓库。M001—M011 的具体契约见 MODULES 和模块 README。

## 分层

- src/app：路由、Node runtime、Cookie／HTTP 和页面适配，调用模块服务。
- src/modules：业务规则、DTO、公开 server/client 入口和组件。浏览器只引用 browser-safe 类型与客户端入口，不引入服务端秘密。
- src/lib/db.ts：持久化单例、getDb 自动迁移和 serializeDatabaseWrite。排队整个事务，不在队列内递归排队；渠道网络调用不占写锁，落库时再校验状态。
- src/lib/schema.ts：聚合模型，关联 users.id；drizzle 保存 0000—0007 SQL、snapshot 和 journal，禁止修改已应用历史。
- src/components：共享导航、语言与布局。部分 lib/components 老文件是兼容导出，新调用遵循模块文档。

## 依赖方向

M001 提供身份 → M008 提供独立角色；M004 公开活动读取使用 M010 发布源 → M002 个人参赛与 M007 组队按活动绑定配置。M009 操作 M002 正式材料、M008 权限及业务审计；M011 发布首页正文 → M005 渲染。M006 读取公开活动信息并展示静态演示项目，不读取私有材料。M003 复用身份、共享 DB 和导航，仍与参赛资格分离且生产禁用。

content-management 的 store 为发布读取核；生产路由用异步 resolveEvent／resolveFiles／resolveCenter 及事务复查，旧同步 forEvent／forCenter 仅静态兼容。不要通过同步 demo 配置绕过下架或更新时间窗口。

## 数据与权限

认证拥有用户、挑战、会话、限流记录、开发邮件。参赛拥有报名、草稿／正式材料、附件；队伍独立持有成员和申请。票务拥有订单、库存、预留、支付与通知。管理员授权和权限审计独立；M009—M011 追加业务审计和结构化发布内容。完整表结构以 schema 和迁移为准，不复制用户实体。

每个受保护页面和接口独立鉴权；业务写事务再检查权限、修订、时间、活动、用户或附件归属。Cookie 仅身份，不是永久权限。内部备注／草稿／认证资料不属于公开 DTO；公开卡片按白名单投影。确认公开意愿、材料审核通过和项目发布是不同步骤。

本地私有文件通过授权 API 访问，public 仅原创公开资产。清理扫描全部活动引用，失败不删除有效附件。PGlite 的共享队列只保证本进程操作，不能作为正式多进程并发方案。

## 部署与实现空白

当前支持本地 Node 单进程持久化。真实邮件、生产 PostgreSQL／对象存储、多进程限流与事务、真实收款、项目投稿发布／互动和最终整合未实现。没有 Docker 配置、生产自动部署或基础设施声明。运行方式和备份约束见 OPERATIONS；CI 只在隔离数据上验收。
