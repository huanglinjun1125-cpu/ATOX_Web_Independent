# M003 开发模拟购票：产品与交互规格

本模块按已批准计划独立实现，不接主站导航或其他业务资格。仅为开发演示，不接真实支付渠道、不发生真实扣款；不能以模拟支付成功作为真实付款或其他模块资格依据。

## 页面与布局

使用两页流程：选票页 → 问卷与订单页。整体浅色背景、清晰边框和卡片层级；桌面双栏，左侧主要操作、右侧订单摘要；手机单栏，摘要与操作按阅读顺序排列。复用站点已有中英文、键盘操作及移动端规范。金额统一明确显示 CNY，所有开发模拟操作显著标记“开发模拟 · 无真实扣款”。

选票页展示票种、价格、剩余库存、数量选择器、每账号最多 5 张及下一步按钮；当前不展示账号动态剩余额度，服务端仍执行限额。问卷与订单页展示已选票、必填问卷、总额、库存预留倒计时、订单状态和相应操作。提交或处理期间禁用重复操作，失败保留可恢复输入，并展示服务端返回的明确原因。

## 票种与购买规则

| 项目               | 默认值           |
| ------------------ | ---------------- |
| 早鸟票             | 49 CNY，库存 100 |
| 标准票             | 99 CNY，库存 100 |
| 单账号累计购买上限 | 5 张             |
| 订单库存预留       | 15 分钟          |

票卡区分可购、售罄和账号额度不足；不可购时说明原因，不仅改变颜色。数量上下限以服务端可购库存和账号额度校验为准。页面展示的库存不代表已锁定，创建订单成功后才显示有效预留。刷新后从服务端恢复订单及剩余时间，不重新开始 15 分钟；倒计时以服务端到期时间为准。

## 问卷

包含显示名称、国家或地区、获知渠道（单选）、参与目的（多选）、备注和政策确认。备注为可选，其余按批准计划与服务端契约校验；政策确认默认不勾选。渠道和目的的具体选项作为演示配置，文案清晰且不暗示正式活动规则。错误紧邻字段显示并可定位，金额和票数始终可核对。问卷内容不作为公开项目资料展示。

## 订单状态与动作

产品呈现区分待支付、支付处理中、已支付、已关闭及已过期；实际订单枚举仅 pending／paid／closed，过期由 closed 与 closeReason=expired 表示。支付失败、取消、不确定分别展示，动作依 canPay、canClose 及服务端结果，不由页面自行推断。关闭后迟到成功标记 reconciliationRequired，不自动恢复订单或退款。

- 待支付：显示预留倒计时、模拟支付入口、取消或返回改票操作。
- 支付处理中：显示处理中并防重复操作；不能在结果未确定时释放库存或开始替代订单。
- 已支付：显示模拟成功、订单编号、票种／数量／总额，隐藏继续支付入口。
- 已关闭／已过期：解释预留失效，提供返回选票入口，不允许对旧订单继续支付。
- 返回改票：先请求服务端安全关闭当前未支付订单并确认释放预留，再返回选票；关闭失败则停留并保留订单。若期间已支付或处理中，展示最新状态，不得仅在前端清空订单。

## 开发模拟面板与边界

开发模拟面板与用户购票操作视觉分组，展示当前订单、模拟结果及反馈，按批准的服务端契约触发模拟成功、失败等事件。重复或过期操作由服务端拒绝或幂等处理；界面不直接改写支付状态、库存和账号额度。

功能受独立开发开关控制，默认关闭；仅开发环境显式开启可用。生产或未开启时，页面、接口及模拟面板均不得开放；隐藏按钮不能替代服务端校验。不向用户收集真实银行卡信息，不展示可造成真实付款的二维码或收款账号。

实际入口为 `/preview/ticketing/demo` 与 `/preview/ticketing/demo/checkout`；开关 ENABLE_TICKETING_PREVIEW 默认 false，本地已开启，且必须 NODE_ENV=development。模拟签名密钥 TICKETING_WEBHOOK_SECRET 至少 32 字符。详细接口、维护与故障边界见 [模块说明](../src/modules/ticketing/README.md)。1.0.0 预备模拟基线已验收：类型／Lint／构建、35 项服务、9 项 E2E、开发关闭开关 1 项及生产 1 项均通过；桌面和手机截图已检查，无横向溢出。

## 验收关注点

两页桌面／手机布局、票态和表单错误可理解；订单金额与数量一致；库存及账号限额服务端生效；刷新与倒计时不延长预留；过期和重复支付安全处理；返回改票安全关单；处理中无矛盾动作；模拟标记持续可见且无真实扣款；开发开关与生产禁用覆盖页面和接口；模块独立且不接主站、参赛资格或真实支付。
