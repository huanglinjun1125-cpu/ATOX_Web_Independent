# M004 多活动看板与活动内参赛流程

按批准计划实现公开活动看板，并把 M002 参赛流程显式绑定活动；保持原 demo URL、数据及报名／提交时间。M003 开发模拟购票继续独立，不接看板或参赛资格。本文仅定义本轮产品与验收边界，不代表正式活动内容。

## 页面层级与导航

主导航增加“活动”，保留原首页；`/events` 为公开深色看板。活动详情 `/events/[eventId]` 是父页面，个人报名 `/events/[eventId]/register` 与材料 `/events/[eventId]/materials` 是子页面；受理页 `/review/events/[eventId]` 同样绑定当前活动。子页清晰返回当前活动及活动列表，不误回其他活动。原 `/events/demo` 及其子页继续可用。

看板及公开 GET `/api/events` 不要求登录，返回仅含公开活动字段的 DTO，不含报名、私人材料、审核意见或内部备注。未知或未发布活动的详情、子页和相关 API 均为 404。

## 看板内容与布局

桌面三列、平板两列、手机单列。卡片包含封面及缺图回退、活动标题、简介／主题、年份、阶段、活动起止时间、地点和查看入口。阶段文字可读，不能仅用颜色表达。中英文切换、键盘焦点、控件标签、图片替代文本及窄屏阅读均需可用。

看板区分正常列表、筛选无结果、无公开活动和加载／错误状态；空状态说明原因并在适用时提供清除筛选。站内活动链接同页打开；配置的外链仅允许 HTTPS，新标签打开并带 noopener；无目标的入口显示“敬请期待”，不生成失效链接。

无筛选时最多展示一个有效且未结束的推荐活动；筛选结果不额外插入推荐项。重复推荐配置视为无效配置，不能随机选择。推荐与阶段均由活动配置和服务端时间确定。

## URL 筛选与排序

筛选条件为 `q`、`year`、`stage`，写入 URL，刷新、复制和浏览器前进后退可以恢复。搜索输入约 300ms 防抖，去除首尾空白，对中英文活动名称／主题不区分大小写检索。年份按活动配置时区下的实际开始时间计算，不按报名时间计算。

阶段以实际活动时间判定：开始前为即将开始；开始时刻包含在进行中，结束时刻不包含；结束时刻及之后为已结束。排序先进行中（结束时间升序）、再即将开始（开始时间升序）、最后已结束（结束时间降序），同值按活动 ID 稳定排序。报名／提交开放状态与活动阶段分别计算，不能用活动阶段代替参赛窗口。

## 演示活动登记

全部时间为 Asia/Shanghai（UTC+08:00）；活动区间及开放区间均开始包含、结束不包含。配置明确标示演示，不能沿用为真实运营规则。

| 标识 | 实际活动时间 | 报名及提交窗口 |
| --- | --- | --- |
| `demo` | 2026-10-01 至 2027-01-01 | 保持原值：2026-10-01 00:00 至 2027-01-01 00:00 |
| `upcoming-demo` | 2027-01-15 至 2027-01-16 | 2026-10-01 00:00 至 2027-01-01 00:00 |

登记与通用路由使用显式活动配置，不通过临时修改全局 eventConfig 切换活动；并发访问不能互相污染。配置为唯一来源，页面日期、阶段和后端开放校验一致。

## 数据与文件隔离审查

现有 M002 表已具备 eventId，报名及材料唯一约束为活动＋用户，本轮不新增表、不重置数据或旧迁移。复用 event_registrations、event_materials、event_assets；报名、材料、上传引用、文件读取、受理列表及操作均绑定明确活动 ID。

文件可继续共用私有上传目录及随机存储名，隔离由元数据和服务端权限完成：同一用户不能把活动 A 文件 ID 引用到活动 B；受理人员也只能读取当前活动正式材料所引用文件。普通用户不能借 ID 访问他人文件或草稿。

只读检查发现 M002 孤儿清理原本扫描全部活动 official／draft 引用；在本轮继续使用这些表的前提下，该保护有效，必须保持全活动扫描，不能改成只保护当前活动。替换清理亦不得删除其他活动仍在引用的文件。维护仍须先停止相同目录 PGlite 服务；共享连接、写队列和现有持久化数据沿用。

## 验收场景

1. 中英文看板三种阶段、推荐、封面回退和链接行为正确；手机单列、平板双列、桌面三列无横向溢出，键盘可操作。
2. 搜索中英文、首尾空白及大小写；组合年份／阶段，URL 刷新、复制、前进后退恢复；空结果可清除筛选，推荐不干扰结果。
3. 在开始／结束边界测试阶段、时区年份及稳定排序；区分活动尚未开始但已开放报名，以及活动已结束且关闭提交。
4. 同账号在两个活动分别报名、保存草稿、提交及受理；版本号、资格、正式资料、意见、附件和状态互不串用。跨活动文件引用／读取及篡改活动请求被拒绝。
5. 两活动并发请求显式配置不串号；未知／未发布活动页面与 API 404，公开列表无私人字段；子页导航返回正确父活动。
6. 清理保留所有活动有效草稿与正式附件；旧 demo 用户、报名、材料及 URL 延续，无数据重置。
7. M001 登录返回、M002 提交／受理与权限、M003 独立模拟支付和禁用边界回归通过。最终测试及 M004 归档由统筹记录，原 M001／M002／M003 归档保持不变。

当前为实现中的设计与验收说明，不宣称最终验证通过。
