# M006 设计与功能边界

日期：2026-10-09。已确认方案：演示项目先行、基础预览弹层、预留投稿入口与契约、允许独立项目或关联一场本站活动。

## 参考产品的逻辑

分析依据为用户提供的截图；两个在线详情页未能直接读取，不推断其隐藏表单、审核或支付逻辑。

- AdventureX 截图偏向跨活动的作品发现：项目卡片包含封面、简介、技术标签及活动线索，详情进一步承载媒体、链接、团队与赛道。
- SheNicest 截图偏向活动作品展陈：分类与搜索帮助找到作品，详情提供介绍、演示链接和支持按钮。
- 二者共有“发现 → 理解 → 互动”层次。M006 聚焦发现，弹层只满足基础理解；完整详情和互动后续独立实现。

## 本站界面

简短主视觉之后立即进入搜索／分类／活动筛选及网格。延续现有 HACKATHON 黑底、紫色与荧光绿，原创几何封面体现作品差异。项目不与推荐活动混排，使搜索结果、数量和分页始终对应同一集合。

卡片内容顺序：封面 → 分类及演示标记 → 名称 → 两行简介 → 最多三个标签 → 创作者展示名 → 所属活动或独立项目。弹层展开完整简介和全部标签；活动链接才离开展区进入 M004／M002。

使用发布时间排序，暂不设置热门、点赞、收藏、奖项或展位统计。示例内容不借用参考站品牌、人物、图片或实际项目。所有项目与创作者明确标注为演示。

## 状态与操作

初始服务端输出当前页，查询操作通过同一公开读取接口更新并写入 URL。搜索防抖；旧请求被取消。加载、错误、无匹配、超出页数分别提供准确反馈。

预览采用原生 dialog，键盘焦点局限于弹层；Esc、关闭和遮罩均可退出。背景滚动暂时锁定，退出恢复焦点与原浏览位置。手机卡片单列，平板双列，桌面三列。

“提交项目”始终进入 `/projects/submit` 说明页，公开可访问，没有假表单或上传成功提示。后续投稿模块复用这个入口；完整详情模块复用稳定项目 ID。

## 数据边界

项目配置与 M002 用户材料完全分离。只依赖 M004 的已发布活动公开信息，项目本身未发布或关联未知／未发布活动时隐藏。未知活动筛选为空，不回退显示全部。

未来投稿输入单独定义，不包含发布批准或可信用户身份。公开输出通过显式字段白名单生成；未来换成数据库读取后也应维持该边界。本轮不预建写 API、业务表或运营后台。
