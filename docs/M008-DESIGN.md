# M008 官方管理后台：管理员权限与入口

本期仅实现 `/admin` 首页、管理员账号管理和权限审计；沿用 M001 邮箱登录，不新建管理员密码登录。材料审核、项目发布、活动内容管理、订单及团队运营均不在本期，不展示可执行的假功能。

## 角色与页面

角色为超级管理员 `super_admin` 和运营管理员 `operator`。运营仅有 admin:access；超级管理员另有 admin:manage 和 admin:audit。权限由服务端持久化角色推导，不依赖客户端标记或旧会话 Cookie 内的角色。

后台首页展示当前身份、角色及已开放入口；账号页提供管理员列表、授权已有验证账号、修改角色及启停；审计页展示权限操作记录。敏感入口和接口均由服务端授权，隐藏菜单不代替权限检查。未登录进入安全登录返回；无权限明确拒绝。手机页面保持字段、反馈和操作可读。

管理员记录字段：userId、email、role、enabled、revision、createdAt、updatedAt、updatedBy。角色变更请求携带当前 revision，过期请求拒绝并要求刷新；不静默覆盖其他管理员操作。禁用保留账号及历史，不删除 M001 用户。

## 初始化与安全操作

首位超级管理员仅通过维护 CLI 初始化到已有、已验证的邮箱账号，不提供浏览器 bootstrap API。命令为 `npm run admin:bootstrap -- --email <已验证账号邮箱>`；先停止使用相同 DB_PATH 的 PGlite 服务。初始化为一次性操作，不能用重复运行 CLI 绕过后台角色管理。

后台禁止自停用或自降级；自身不改变值的请求无需失败。保留至少一位有效超级管理员。权限变更进入共享写事务，身份及权限每请求核验，撤权后已有会话不能继续使用旧权限。bootstrap 必须同时不存在任何管理员记录和 bootstrap 审计；永久初始化记录保证禁用后也不能重新初始化恢复权限。

## 审计字段与可见性

审计 action 为 bootstrap、grant、update；actor 包含 source（web／bootstrap）、可空 userId 和 label。记录目标 userId／email、before（首次授权为空）、after 与时间；快照包含 email、role、enabled、revision。权限变更及审计同事务落库，不提供编辑或删除审计入口。审计仅记录管理员权限操作，不能宣称覆盖尚未开发的业务审核历史。

账号与审计分页均为 20 条，返回 items、total、page、pageSize、totalPages。仅在授权范围提供邮箱及内部信息，不进入任何公开 DTO。

## 现有 M002 边界与后续路线

本期管理员角色不自动获得原 EVENT_REVIEWER_EMAILS 材料受理权限，也不通过账号界面改变材料状态。现有 M002 接受／拒绝都会进入 processed 并只读；需补充仅在开放期允许重提，截止限制继续生效。

后续单独实施材料审核后台，按已批准方向把“驳回可修改重提”纳入状态、截止和历史版本设计；本期不提前改变旧规则。审核与公开发布分别记录：接受不等于上线，publicDisplay 仅展示意愿。再实施真实项目投稿及发布／下架，明确公开字段、授权与已审核版本绑定，不直接公开私人 PDF、邮箱或内部备注。活动、团队和订单运营继续分别定义权限与验收。

## 验收场景

验证未登录返回、普通用户拒绝、运营／超级权限区分、CLI 首次初始化、同目标重复幂等和不同目标拒绝、仅已有验证账号可授权、自改拒绝、最后有效超级保护、修订冲突、并发角色修改、撤权立即生效、重启持久化及完整权限审计。回归原邮箱登录、材料白名单受理、组队、公开展区及模拟购票，确认无数据重置或业务权限扩大。

本文件为实现规格，实际测试和留存结果由统筹记入验收文档；本期不承诺已具备生产上线条件。
