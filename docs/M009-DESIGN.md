# M009 现有选手正式材料审核

日期：2026-10-10（Asia/Shanghai）。已授权独立实施的第一子模块；本文件为产品契约，最终 API、迁移与验证以模块实现及验收记录为准。

## 范围与权限

官方后台审核现有 M002 个人正式材料，不接收真实独立项目投稿、不审核用户草稿、不实现项目公开发布或团队统一提交。审核通过不等于在 M006 项目展区发布。

有效超级管理员、运营管理员可以审核；所有页面、查询、附件及写接口服务端核验 M008 当前角色和 enabled，写事务再次核验。新管理员角色取代业务邮箱白名单授权，旧 EVENT_REVIEWER_EMAILS 账号不会自动成为管理员；旧受理入口及附件旁路也必须统一新授权，不能只保护新后台页面。停用后已有会话即失去审核权。

## 列表、详情与字段

审核列表只包含有 official 的记录，支持活动及审核状态筛选、分页和明确空／错误状态。详情固定当前活动及材料标识，展示提交人必要报名信息、正式材料及附件、提交时间、修订号、审核结果、用户可见意见和内部备注；不混入修改草稿。审核按钮为通过、驳回，驳回原因必填，原因紧邻操作验证。

材料字段保持现有 name、tagline、description、trackId、coverId、screenshotIds、documentId、videoUrl、experienceUrl、codeUrl、original、usageAuthorized、publicDisplay。正式提交继续要求名称、简介、描述、有效赛道、封面、PDF、原创及使用授权；截图／链接和展示意愿非必填。报名邮箱及联系方式仅用于内部审核，不进入公开项目字段。内部备注仅管理员可见，驳回原因通过 publicNote 向本人展示。

## 状态投影与兼容

| 存量状态 | 新展示状态 | 选手操作 |
| --- | --- | --- |
| not_submitted，无正式资料 | 未提交，不进入审核列表 | 开放期保存草稿／提交 |
| pending | 待审核 | 开放期修改草稿并重提 |
| needs_changes | 驳回 | 开放期补充重提 |
| processed + rejected | 驳回 | 本期改为开放期可修改重提 |
| processed + accepted | 通过 | 只读 |

这是对既有 rejected 只读规则的明确变更，不批量重写或删除历史数据。现有 needs_changes 记录的用户可见意见继续作为驳回／补充反馈保留；历史空原因不得伪造，界面可提示未留原因。新驳回必须保存非空原因。通过保持只读，不提供隐含撤销通过或重新开放操作。

用户已确认沿用原提交截止：开始包含，截止不包含。驳回不会自动延长窗口，截止后仍只读，不开放补交例外。本模块不改报名成功即资格或组队规则。

## 正式版本、冲突与附件

official 与 draft 独立；保存草稿不改变审核对象。重提后正式版本替换、草稿清空，结果与当前意见清空，进入待审核；不能把旧意见展示成新版本结果。审核请求核对 revision 与 submittedRevision，冲突保留操作输入并要求重新核对，不覆盖选手或其他管理员的新版本。列表刷新保持当前选中材料和输入，对过期版本禁用提交。

附件仍为鉴权私有文件；校验活动、所有者、用途及正式引用。审核人员只能通过被授权的正式材料读取附件，不能读取未提交草稿。清理保护所有活动有效 official／draft 引用，不能因驳回误删资料。沿用共享连接及写队列，不重置用户、材料或旧迁移。

审核操作留存操作者、活动／材料、所审核提交版本、前后状态、用户意见／内部备注及时间；业务审核记录与 M008 权限审计分开，不假称原权限审计已经覆盖材料操作。意见和状态同事务提交。

## 验收

两类管理员可审核，普通用户及仅白名单账号拒绝，撤权立即生效；各活动／用户隔离；只显示正式资料；通过只读；新驳回缺原因失败；旧 needs_changes 和 rejected 开放期可重提，截止仍阻止；重提恢复待审核不沿用旧结果；双修订冲突保留输入；并发只允许匹配版本成功；内部备注不下发本人或公开接口；附件与清理安全；审核记录完整；原登录、组队、公开展区及模拟支付回归，旧数据保留。
